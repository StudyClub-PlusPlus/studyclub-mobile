# MyPage · SC94 인증 통합

기존 [MyPage #94](https://app.notion.com/p/benkang/3d283feabad38098a5c9fb0d420ac198)와 PR9의 프로필 의도를 보존하고 SC51/52 인증 정책에 연결한다. 원본 커밋5d1b7fb는 archive ref와 과거 증거에서 보존한다.

`account.mypage` ON은 스터디/내 스터디 두 탭과 양 루트의 우측 프로필 버튼을 제공한다. 프로필은 자체 UINavigationController로 fullScreen 표시한다. 닫기는 원래 선택 탭과 두 탭의 탐색 스택을 보존한다. OFF는 이전 Main/Setting 구조다. `auth.google-login`은 별도 InProgress 기본 OFF이며 인증 요청과 진입을 제어한다.

프로필은 기존 AppTheme·스크롤 카드·시스템 프로필 심볼을 사용한다. SC52의 계정 표시 모델과 인증 presentation/cleanup을 공유하며 별도 AccountRepository·DTO·클라이언트·메모리 토큰을 만들지 않는다. 회원에게 확인된 닉네임과 로그인됨을 표시한다. 이메일과 가짜 데모 세션은 추가하지 않는다. 비회원은 명시적으로 로그인하며 checking·재확인 실패·로그아웃 실패를 구분한다. 로그아웃 실패는 회원 정보와 재시도를 유지한다.

프로필에서 시작한 로그인 성공·취소는 열린 프로필로 돌아온다. 내 스터디의 비회원 안내에서 시작한 로그인은 같은 계정 흐름을 사용하며 성공·안전한 취소 뒤 원래 화면으로 돌아온다. 실패·가입 결과 불확실·정리 실패는 기존 Auth 정책대로 확인/재시도를 유지한다. 닫기는 미완료 정리를 성공으로 바꾸지 않는다.

내 스터디는 SC94에서 안내만 제공한다. LIST/API/세션 갱신 연결은 SC65~68, 캘린더는 별도 작업이다. 프로필 수정·원격 이미지·신청·탈퇴는 추가하지 않는다.

기존 캡처와58개 테스트 주장은 당시 단독 PR9 후보에 대한 역사적 근거다. 새 후보의 빌드·상태별 신선 캡처·정상 크기 상호작용·fullScreen 복귀·탭 스택 보존 확인은 QA/디자인 담당자의 정확 후보 결과로 연결한다. 로컬 Mock·통제 화면은 실제 OAuth·서버·약관 검증을 대체하지 않는다.

## 정리 실패 시 닫기

프로필 닫기에서 계정 정리가 실패하면 프로필과 실패 안내를 유지하고 같은 정리만 재시도한다. SettingViewController는 실제 자식 인증 navigation controller가 있고 현재 제시된 화면과 같을 때만 그 자식을 닫는다. 자식이 없는 nil/nil 비교로 프로필 자체를 닫지 않는다. 정상 프로필 닫기는 원래 선택 탭과 navigation stack으로 돌아간다.
